# PROGRESS / BOOTSTRAP — Kobra 3 Max G-code documentation project

*Last updated: 2026-11-13 (ch.25 added). Read this file first when resuming the work in a new session.*

## 1. Goal

Produce a **user-friendly G-code / macro guide** for the Anycubic Kobra 3 Max (firmware **2.5.2.8**, "Klipper-Go"), based **only on analysis of the binary firmware** (`gklib`). The public GitHub source (`Klipper-go/`) is **stale** — use it at most as a hint for what a command probably does, never as the source of truth (the firmware has M600/M601, SET_PAUSE, M8844, LeviQ3, filament hub, …, and lacks M20–M30 etc.).

The user wants, for each command/macro:
- a precise, plain-language description of its effects (step by step),
- a detailed description of every parameter: meaning, possible values, default,
- examples,
- **no technical references to firmware internals** (no Go function names, offsets, etc.) in the user guide,
- written **in small chunks, in the order of the "full command table"** (categories below), stopping after each chunk for the user's review.

## 4. Analysis toolchain (`analysis/`)

Environment: Windows, Git Bash + PowerShell. Python 3.15, **no venv** (venv creation fails because the scratchpad path contains `;`). Libraries installed with `pip install --target analysis/libs capstone pyelftools`. Run scripts from `analysis/` with `PYTHONPATH=libs python <script>`.

**Traps already hit:**
- Never name a script `dis.py` (shadows stdlib `dis`, breaks capstone import) — helper is `gdis.py`.
- Capstone must run with `skipdata=True` (literal pools sit inside functions; otherwise functions are truncated) and every consumer must skip `ins.id == 0` pseudo-instructions.
- The Bash tool choked on a long heredoc with quotes → use the Write tool for long files.
- `strings`, `objdump`, Go toolchain are not installed. `grep -a -o` works for raw string hunting.
- Do not run anything from inside extracted/untrusted firmware directories.

**Binary facts:** ELF32 ARM, Go (stack ABI on ARM32, so call arguments are on the stack at `[sp+4]…`), pclntab magic `0xfffffff1`, 16 620 named functions in package `k3c/klippy`. Method values appear as `…-fm` wrappers; a registered command's handler = the `-fm` function whose address is loaded just before the `Register_command` call. Strings are (ptr,len) pairs: `ldr rX,[pc,#n]` + `mov rY,#len`. Doubles come from literal pools via `vldr`.

## 5. Key findings so far (full detail in `K3M_2.5.2.8_gcode_commands.md` and the guide)

- **M600 and M601 are aliases of `PAUSE`** (same handler). The command only saves state (`SAVE_GCODE_STATE NAME=PAUSE_STATE`), pauses the print-job reader and fires event `virtual_sdcard:pause_print`; the physical park/retract/temperature drop is done by the filament-hub module's listener. `RESUME [VELOCITY=]` restores the state. `SET_PAUSE` just sets the paused flags. `M25` (SD pause) is **not** registered in this firmware (M20–M30 are gone).
- **M8844** = emergency shutdown like M112 (parses an `S=` text).
- G9111/G9112/G9113: nozzle-clean memory counter + pre-print sequence (see guide chapter 2). Decoded stock-config values: `[leviQ3]` `extru_temp` 170 (WIPETEMP default), `extru_end_temp` 140 (probe temperature), `bed_temp` 60.
- `BED_MESH_OFFSET` is broken (index out of range + lowercase parameter names).
- **`BED_MESH_CALIBRATE ADAPTIVE=1` (verified in disassembly + sample G-code files + live mesh query):** implemented and logically sound but **dormant in normal prints**. Data source: at print start (`SDCARD_PRINT_FILE` / power-loss resume → `FilamentHub.check_ready` → background goroutine `parse_t_commands`) every file line goes through `VirtualSD.ParseExcludeObjectOffset` → `AdaptiveBedMeshInfo.parse_adaptive_bed_mesh`, which only accepts lines starting exactly with `; print_bed_min =`, `; print_bed_max =`, `; first_layer_print_min =`, `; first_layer_print_max =` (values `x,y`). Valid only if all four parsed (NaN-initialised in `NewVirtualSD`; reset at print exit/cancel). `set_adaptive_mesh`: bounds = first-layer bbox ± `ADAPTIVE_MARGIN`, clamped to configured mesh area; enlarged to `min_bedmesh_area_size` (default 100,100) if smaller; probe counts = ceil(count × size ratio); silent fallback to full mesh if info invalid (message only if the VirtualSD object is missing). Only caller of `BED_MESH_CALIBRATE ADAPTIVE=1` in the firmware: `LEVIQ_PROBE` (touchscreen leveling, no print running → always full mesh). Documented in guide chapter 3 ("Adaptive mesh in detail"). Never tested on the printer.

- **ERROR SEMANTICS (found in ch.15/16 2nd pass, important):** `GCodeDispatch.Process_commands` treats a handler that *returns* a non-nil `error` as an internal error: logs, `Invoke_shutdown("Internal error on command: X")` (printer enters shutdown, needs FIRMWARE_RESTART), `Respond_error`, re-panics. Errors raised with `panic(...)` (e.g. `Get_float` "Error on '%s': missing %s", most command errors) are recovered by the webhook `_handle_script` and shown on the console only, no shutdown. In the binary a handler error is a `fmt.Errorf` *returned* (e.g. SET_GCODE_VARIABLE `Unknown gcode_macro variable`, macro `called recursively`) vs `fmt.Sprintf`+panic. **TODO (optional audit):** earlier chapters list many error messages (e.g. `Unknown sensor %s`, `Unknown stepper`, PCBA_WRITE…) — check for each whether it is returned (→ shutdown) or panicked (→ console only) and say so in the guide.
