# Kobra 3 Max (K3M) firmware 2.5.2.8 — G-code command reference recovered from `gklib`

Source: `K3M_2.5.2.8/update_swu/app/gklib` (ELF32 ARM, Go, stripped, ~13 MB, package `k3c/klippy`).
This is the closed, newer build of the Klipper-Go code published at github.com/ANYCUBIC-3D/Klipper-go.
**The public repo is older**: it lacks M600/M601, SET_PAUSE, M8844, M73 handling, LeviQ3, the filament hub, etc.

## How this was obtained (reproducible, scripts in `analysis/`)

1. `pcln.py` parses `.gopclntab` (Go pclntab, magic `0xfffffff1`). Symbols survive stripping: **16 620 named functions**.
2. `gdis.py` / `trace.py` disassemble ARM32 with capstone (skipdata on, because literal pools sit inside functions) and track `ldr rX,[pc,#n]` / `mov` / `str rX,[sp,#n]` to recover the stack-passed arguments (Go on ARM32 uses the stack ABI) of every `bl`.
3. `cmds.py` finds every call to `GCodeDispatch.Register_command` / `Register_mux_command`: command name, help string, and the `...-fm` method-value wrapper that identifies the handler. Commands registered in loops over string slices (`NewGCodeMove`, `NewGCodeDispatch`, `FilamentHub`) are recovered by `strs.py` (string literal pairs) and matched to handlers by method name.
4. `params.py` walks each handler (and callees up to 3 deep, plus its closures) and records string arguments of `GCodeCommand.Get/Get_int/Get_float/Get_floatP/Has` → parameter names and, when statically readable, defaults.
5. `summ.py` prints an ordered call trace with string arguments (for example the G-code a handler runs) for behaviour analysis.

**Limits:** no decompiler was used; behaviour descriptions come from call traces, not full control flow. "Parameters" lists the names a handler reads; defaults are literal defaults read from the binary (missing = no default, optional, or not statically resolvable). Handlers that read parameters through interface calls, `Get_command_parameters()` or helper types may show fewer parameters than they accept (for example `G1`, `G28`, `M104` also accept the usual X/Y/Z/E/F/S/T letters). 175 commands were found; user macros from `printer.cfg` are listed separately.

## Key finding: M600 / M601

`NewPauseResume` registers **`PAUSE`, `RESUME`, `SET_PAUSE`, `CLEAR_PAUSE`, `CANCEL_PRINT`, `M600`, `M601`**. `M600` and `M601` are registered with the **same handler as `PAUSE`** (`(*PauseResume).cmd_PAUSE`, help text "Pauses the current print"). They take no parameters; any given are ignored.

`cmd_PAUSE` (0x64b5c0) does, in order:
1. If already paused: respond "Print already paused" and return.
2. `send_pause_command`: if a virtual-SD print is active, `VirtualSD.do_pause()` (stops the SD reader), otherwise emit `action:paused`.
3. `Run_script_from_command("SAVE_GCODE_STATE NAME=PAUSE_STATE")`: saves position, speed, extrusion mode.
4. Set `is_paused = true`, then fire the event **`virtual_sdcard:pause_print`**.

The physical pause motion is **not in the command handler**. It is the listener `(*FilamentHub).pause_print` (event `virtual_sdcard:pause_print`). From its call trace: set fan speed, lower the nozzle heater to a pause temperature and wait, stop ACE feed-assist, RFID handling, **require XYZ homed**, then `Toolhead.Manual_move` calls for the Z lift (`move_z`), extruder retract (`move_e`) and a move to the park position, then `Wait_moves`. The `[pause_resume] pause_position` key (X,Y park position; K3M: `457,420`) is read by `NewPauseResume` (`Getfloatlist`). `z_up`, `extru_pull` and `bee_path` in the same config section are not read by `NewPauseResume`; they are read elsewhere (not traced).

`RESUME [VELOCITY=]` (0x64b7a0): requires paused state; fires `virtual_sdcard:pre_resume_print` (handled by `FilamentHub.pre_resume_print`: moves to the sweep position, runs `M109 S<pause_temp>`, re-primes), then `RESTORE_GCODE_STATE NAME=PAUSE_STATE MOVE=1 MOVE_SPEED=<VELOCITY>`, `do_resume()`, and clears the paused flag.
`SET_PAUSE` (no params): only sets `is_paused` and `pause_command_sent` to true (no motion, no SAVE_GCODE_STATE). Used to mark the state when the pause was done by other code (for example filament runout).
`CLEAR_PAUSE`: clears the flags without resuming. `CANCEL_PRINT`: `VirtualSD.do_cancel()` + `delete_record` (power-loss record), then clear pause.
Related: `RUNOUT_PAUSE` (filament hub) = sanity check, stop feed assist, run script, `post_clean_pipe`, `do_pause("RUNOUT_STATE")`.

Pausing with `M25` therefore does **not** work in this firmware; use `PAUSE`, `M600` or `M601`.
